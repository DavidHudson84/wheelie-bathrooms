# Wheelie Bathrooms website

wheeliebathrooms.com.au. Static site generated by `build/build.mjs` (Node, no dependencies), hosted on GitHub Pages, with a Supabase backend (project `wheelie-bathrooms`, ref `qakzwoopjnbwjqnyuiuo`, Sydney).

## How it fits together

- **Public pages** are generated at build time. Blog posts and FAQs are read from Supabase, so edits made in the admin page go live on the next hourly build (or push to `main`).
- **Quote form** posts to the `enquiry` edge function, which saves the enquiry and emails info@ through Resend.
- **Admin** (`/admin/`) uses Supabase Auth (email + password). Only emails in `public.admins` can read anything; every table has row level security.
- **Hire agreements**: from a hire in admin, *Email agreement* sends the customer a link to `/sign/?t=<token>`. They check the details, accept the terms, upload their licence and sign with a finger. Licences go to the private `licences` storage bucket.
- **Hire reminders**: pg_cron `wheelie-hire-reminders` runs at 22:00 UTC (8am AEST, 9am AEDT) and calls the `hire-reminders` function, which emails customers 7 and 2 days before the end date (bcc info@) and flips booked hires to on hire on their start date. Dry run: `select public.trigger_hire_reminders(true);`

## Hire billing (replaces Stay on Hire)

- **Tables:** `customers` (who pays: trade or residential, bill in advance or arrears, cycle, terms, Xero ContactID), `units` (fleet, default $/day), `hire_items` (assets on a hire with their own rate and on/off dates, `billed_until` is exclusive), `hire_charges` (one-off extras), `invoices` (what was raised, with Xero ids and status).
- **Maths:** `supabase/functions/_shared/billing.ts`, pure and tested by `node supabase/functions/_shared/billing.test.mjs`. Trade: every N days in arrears (or advance), final pro-rata at off-hire, credit note for unused advance days. Residential: billed up front to the booked end date, due on issue, no refund for early return (T&C clause 4). Mobilisation goes on the first invoice. Line text copies the Stay on Hire layout.
- **Function `billing`:** `preview` (what's due today), `raise` (DRAFT invoices or credit notes in Xero, or "billed elsewhere"), `sync` (status and payments back from Xero, hourly via pg_cron `wheelie-xero-sync`; a voided draft rolls the billed-to dates back). Never approves anything.
- **Xero:** its own app ("Wheelie Hire"), connected from admin > Billing; the callback (`xero-callback` function) keeps only the Wheelie Bathrooms org and disconnects any other ticked by mistake. Tokens in `private.settings`. Account 200, tax OUTPUT, the existing branding theme.

Secrets (Resend key, cron secret, sender, site URL) live in `private.settings` in the database, never in this repo.

## Build locally

    node build/build.mjs                              # real-domain build, noindex
    BASE_PATH=/wheelie-bathrooms node build/build.mjs # as the github.io preview

`build/images.py` regenerates `assets/img` from the Dropbox photo folders. `build/seed-sql.mjs` produced the first FAQ and blog load from `build/content.mjs`.

## Going live on wheeliebathrooms.com.au

1. Add a `CNAME` file containing `wheeliebathrooms.com.au` and push. The build then drops the `/wheelie-bathrooms` prefix and allows Google to index.
2. At the domain's DNS host: A records for `@` to 185.199.108.153, 185.199.109.153, 185.199.110.153, 185.199.111.153, and CNAME `www` to `davidhudson84.github.io`. Leave the MX records alone (email).
3. In GitHub repo Settings > Pages, set the custom domain and tick Enforce HTTPS.
4. `update private.settings set value = 'https://wheeliebathrooms.com.au' where key = 'site_url';`
5. In Supabase Auth > URL configuration, set Site URL to `https://wheeliebathrooms.com.au/admin/`.
6. Submit `https://wheeliebathrooms.com.au/sitemap.xml` in Google Search Console.
